# Playwright 自动化测试 Demo

> 基于 **Playwright + TypeScript + Page Object Model** 的自动化测试演示项目
> 覆盖 UI 功能测试、接口测试、CI 自动回归，并体现 AI 辅助测试的实践与边界把控

---

## 项目简介

这是一个完整、可运行的 Web 自动化测试项目，演示了自动化测试岗位的核心工作流：**用例设计 → 自动化脚本编写 → UI 与接口测试 → CI 持续回归 → 测试报告输出**。

项目以业界通用的 TodoMVC 应用为被测对象（公开站点，模拟"测试他人开发的产品"这一真实工作场景），重点不在被测应用本身，而在于其中体现的测试方法论与工程化结构——这些技术同样适用于复杂的企业级业务系统。

---

## 技术栈

| 技术 | 说明 |
|------|------|
| **Playwright** | 微软开源的现代 Web 自动化测试框架 |
| **TypeScript** | 类型安全，工程可维护性强 |
| **Page Object Model** | 主流测试设计模式，元素与用例解耦 |
| **GitHub Actions** | CI 持续集成，提交代码自动跑回归 |

---

## 项目亮点

**1. 采用 Page Object Model 分层架构**
页面元素定位与操作封装在独立的 Page Object 类中，测试用例只调用业务方法、不直接耦合页面细节。页面改版时只需修改单一文件，所有用例自动生效，显著提升可维护性。

**2. 用例设计体现系统化测试思维**
不止覆盖正常流程，还运用 **等价类划分、边界值分析、场景法、状态转换** 等测试用例设计方法，覆盖了空输入、超长文本、特殊字符、不存在资源（404）等边界与异常场景。

**3. UI 测试 + 接口测试双覆盖**
UI 层验证用户可见行为；接口层直接验证后端数据正确性，覆盖 GET/POST/PUT/DELETE 及异常状态码。两者互补，能发现"界面正常但底层数据错误"的隐藏缺陷。

**4. 配置 CI 持续回归**
通过 GitHub Actions 实现每次代码提交自动运行全部测试并产出报告，对应自动化测试中"回归验证"的工程实践。

**5. 稳定性优先的定位策略**
优先采用 `getByRole` / `getByText` / `getByTestId` 等贴近用户视角的稳定定位方式，规避对页面结构强依赖的脆弱定位，降低用例 flaky 风险。

---

## 关于 AI 辅助测试

本项目在开发过程中使用了 AI 编程工具（Claude / Cursor）辅助生成 Page Object 与用例初稿，随后进行了人工 review 与完善：修正了 AI 倾向生成的脆弱定位器、补强了偏弱的断言、并基于测试思维补充了 AI 未覆盖的边界与异常场景。

这一过程也反映了对 AI 工具边界的认知：**AI 适合加速初稿生成与重复劳动，但"该测什么、结果是否正确、风险在哪"等核心判断仍需由测试人员把关。AI 是提效工具，不替代测试思维。**

## 快速开始

环境要求：Node.js 18+

```bash
# 1. 安装依赖
npm install

# 2. 安装 Playwright 浏览器
npx playwright install

# 3. 运行全部测试
npm test

# 4. 查看 HTML 测试报告
npm run report
```

常用命令：

| 命令 | 说明 |
|------|------|
| `npm test` | 运行全部测试（UI + 接口） |
| `npm run test:ui` | 仅运行 UI 功能测试 |
| `npm run test:api` | 仅运行接口测试 |
| `npm run test:headed` | 可视化运行（显示浏览器操作过程） |
| `npm run report` | 打开 HTML 测试报告 |
| `npm run codegen` | 启动录制功能，自动生成脚本 |

## 测试覆盖范围

**UI 功能测试**
- 待办的增、删、改、查正常流程
- 多条数据批量操作与计数校验
- 完成 / 重新激活的状态流转
- 边界与异常：纯空格输入、超长文本、特殊字符与表情

**接口测试**
- GET 列表 / 单条查询：状态码、响应结构、字段完整性校验
- POST 新建：状态码 201 与数据回显校验
- PUT 更新 / DELETE 删除
- 异常路径：请求不存在资源返回 404
